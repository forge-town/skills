# Introspect Best Practice 反思流程

## 第一阶段：假设挖掘

针对目标 best-practice，回答以下问题：

- [ ] 这个规范建立在什么**未明说的假设**之上？
  - 例："每个组件必须有单元测试" 假设了 "所有组件都值得测试成本"
  
- [ ] 规范的**适用边界**在哪里？
  - 什么场景下这个规范**不应该**被遵循？
  
- [ ] 规范的**成本**是什么？
  - 时间成本、认知成本、维护成本、灵活性损失

## 第二阶段：盲区扫描

### 2.1 遗漏场景
- [ ] 规范是否覆盖了**异常流程**？
- [ ] 规范是否覆盖了**小规模项目**vs**大规模项目**的差异？
- [ ] 规范是否考虑了**团队经验水平**的差异？
- [ ] 规范是否覆盖了**紧急交付**场景？

### 2.2 过度设计
- [ ] 规范中是否有"为了规范而规范"的条款？
- [ ] 哪些规则带来的收益**小于**执行成本？
- [ ] 规范是否强制了**不必要的统一**（扼杀合理差异）？

### 2.3 自我矛盾
- [ ] 规范内部是否有**相互冲突**的条款？
- [ ] 规范是否与项目其他约束冲突？

## 第三阶段：替代方案

- [ ] 如果**完全相反**的做法，在什么情况下会更好？
- [ ] 是否存在**更轻量**的替代方案达到相同目标？
- [ ] 规范是否可以**分层**（新手 vs 专家不同要求）？

## 第四阶段：输出反思报告

```
## 反思报告: {best-practice-name}

### 发现的盲区
1. {具体盲区及场景}

### 疑似过度设计
1. {条款} - 原因: {...}

### 改进建议
1. {具体改进建议}

### 需要废弃的规则
1. {规则} - 替代: {...}

### 新增建议规则
1. {基于盲区发现的新规则}
```
