# 投入时长与原生计点

## 计点口径

1 小时投入 = 1 点。以同一个 Issue 的累计投入为单位，先汇总再向上取整：estimate = ceil(累计秒数 / 3600)。30 分钟为 1 点、60 分钟为 1 点、61 分钟为 2 点；没有投入为 0，不为零工作创建 Issue。

两段 30 分钟合计 1 点，不能分别取整成 2 点。前次累计 30 分钟已记 1 点，本次新增 10 分钟，累计 40 分钟仍为 1 点。不同 Issue 分别累计；共同测试、调研或并行任务的共享时间只能分配一次。

新建和复用 Issue 都将该结果写入 Linear 原生 estimate，替换原计划估点。不能只在评论里写“参考点数”，却保留原来的 8/16 点，也不能把实际点数加到原计划点数上。

## 时间来源

优先采用实际计时、工时记录或用户确认的投入，记录工作人、时长、范围及来源。没有精确计时时，默认依据 Git 与会话作回顾估算：调用本技能执行补录即包含这一口径，不再询问是否允许估算或索要计时器记录。结合实际 PR 改动、提交顺序、测试记录与会话工作阶段判断有效投入，逐项写明估算依据及不确定性；不得将估算称为精确计时。用户明确提供实际时长或要求不用估算时，以用户要求为准。

Git 能确认改动范围、作者、日期和先后关系，不能单靠首尾 commit 时间差认定连续投入。不能按代码行数、文件数、mtime 或聊天跨度机械换算小时；排除闲置、机器等待和重复分配的并行时间。仅在 Git 与会话证据仍不足以作合理估算、已知实际记录冲突或用户明确禁止估算时，保留对应计点草稿并询问具体缺失信息；不得仅因没有精确计时再次询问估算授权。

工作发生日期与本次补录日期分别记录；不得为补过去统计而伪造历史创建/完成时间，或自动改变 Cycle。

## 已有点数与增量

先查实际记录和历史评论，识别已记时段。已有 estimate=8 不证明投入了 8 小时。

- 原值只是计划估点：用本次覆盖范围的实际投入替换。例如原来 8 点、实际投入 2 小时且无其他实际记录，更新为 2 点，不保留 8 点，也不写成 10 点。
- 已有实际时间账：此前已记录投入 + 本次未记录投入 = 新累计投入，重新取整；不要直接加“本次取整点数”。
- 相同工作或时段已记录：不增加时长或点数；仍可补齐错误或缺失的状态、负责人。
- 旧点数来源不明：检查可用实际记录，明确本次补录覆盖的范围；按该范围投入计点并披露历史时间缺口，不因缺少全量历史计时而默认保留计划估点。存在已知实际记录冲突时先核清，不能无声覆盖。

时间账与完成情况独立：投入过时间不证明全部完成；Done 也不能证明精确投入。回顾估算仍按用户授权口径写入原生点数，并保留来源标注。

## 离线计算器

[calculate-points.py](../scripts/calculate-points.py) 只计算数值，不推断时长、不访问 Git/Linear、不更改文件。参数为每段新增投入的整数秒数；已有实际累计通过 --previous-seconds 传入，不能用原计划 estimate 反推。

```bash
python3 scripts/calculate-points.py 1800 1800
python3 scripts/calculate-points.py 600 --previous-seconds 1800
python3 scripts/calculate-points.py 7200
```

以上依次得到累计 1、1、2 点。previous_points 是前次秒数对应的计算值，不证明 Linear 已写入该值；写入前仍核对原字段及实际记录。
