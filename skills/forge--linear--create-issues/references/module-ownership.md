# 按模块分配负责人

创建 Issue 前读取真实项目描述、对应模块标签描述及当前用户信息，核对项目内有效的模块负责人绑定。不要仅凭其他项目的同名标签或一条旧 Issue 猜负责人。

1. 当次用户明确指派优先；否则使用对应项目的模块绑定。标签描述是绑定来源，项目描述可以汇总展示。
2. 将绑定人解析为当前 workspace 的有效用户 ID，填写表单 assignee，再由生成器映射原生 Assignee；写入创建请求时一起设置，不只在正文写名字，也不先建成未分配后遗漏。
3. 多个模块归属同一人可以直接分配；归属不同人时先明确主模块，或按用户要求拆分。没有绑定、人员已停用或同名用户不唯一时，先完成可确定的草稿并向用户补齐分工，不自行猜测或把空负责人当作完整交付。
4. 仅本地 review 不分配线上 Issue。更新已有正文时保留已有明确指派；只有用户授权调整负责人或同步模块分工时才改 Assignee。
5. 用户修改分工时，先更新模块标签描述及项目汇总，再按获授权范围调整现有 Issue。回读 Assignee、模块、项目、估点和状态，确认正文及未授权属性不变。

这里的“自动分配”指 Agent 在创建流程中按绑定填写 Assignee，不代表配置了 Linear 后台触发器，也不替其他用户或外部系统的创建行为自动执行。
