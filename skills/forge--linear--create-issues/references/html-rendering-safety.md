# HTML 静态渲染与故障防护

## 适用范围

所有由 Issue Markdown 生成的 `issue.html` 都必须遵循本规范。目标是保证文件直接打开时一定能阅读完整 PRD，即使 JavaScript 被禁用、脚本执行失败或浏览器限制本地脚本。

## 已知故障模式

曾出现过以下链路：

1. 生成器只在 HTML 中写入标题、空的内容容器和一段客户端 Markdown 渲染脚本。
2. 完整 Markdown、SVG 和原型被序列化进脚本字符串，而没有作为静态 DOM 写入页面。
3. 生成器使用模板字符串拼接脚本；正则表达式中的反斜杠在多层字符串处理中丢失。
4. 浏览器解析到损坏的正则表达式后产生语法错误，渲染函数完全没有执行。
5. 文件大小、Markdown 文本、SVG 标签和原型字符串仍然存在于脚本源码中，因此简单文本搜索错误地报告“内容齐全”。
6. 用户实际打开页面时只能看到外壳，正文区域为空。

这个问题的本质不是内容没有生成，而是核心内容只存在于不可执行的脚本数据中，没有进入浏览器可呈现的 DOM。

## 强制生成方式

- Markdown 在构建阶段转换为静态 HTML，标题、摘要、Task、流程图、原型、非目标和验收标准直接写入 `<body>`。
- 核心 PRD 不得依赖 `DOMContentLoaded`、`innerHTML` 注入、客户端 Markdown Parser 或前端框架挂载后才出现。
- JavaScript 只用于可选交互，例如 Tab、筛选、原型状态切换；脚本失败时仍能阅读全部产品规格。
- Graphviz 或 Mermaid 在构建阶段生成自包含 SVG；不得要求页面加载后从 Mermaid 源码再次渲染。
- 生成器必须先校验 Markdown、Flow Schema 和原型输入，再一次性输出 HTML；校验失败时不得覆盖上一份可用产物。
- 动态文本进入 HTML 前必须完成 HTML escaping；进入 JavaScript 字符串时还必须单独处理脚本终止序列和字符串转义。
- 若确实需要内嵌脚本，脚本必须独立通过语法检查，并且不得持有页面唯一一份正文。

## 上传前验证

验证必须针对浏览器最终可见结构，而不是原始源码中任意位置出现的字符串：

- 使用 HTML Parser 或浏览器 DOM 查询确认两份语言正文都包含实际文本节点。
- 在禁用 JavaScript 或页面脚本尚未执行的条件下，仍可找到标题、全部 Task、全部 AC、流程 SVG 和原型容器。
- DOM 中不存在承担核心渲染职责的空容器，例如只有 `<div id="content"></div>` 而正文全部位于 `<script>`。
- Task、AC、流程节点、流程边和原型数量从解析后的 DOM 或结构化源取得；不得用 `rg`、`grep` 对包含序列化脚本数据的整份 HTML 直接计数并据此判定通过。
- 若 HTML 包含脚本，执行语法检查并检查浏览器 Console 不存在 error；脚本关闭后再次确认核心正文仍然存在。
- 检查 1440px、1024px 和 390px 宽度，确认页面级无横向溢出，流程图和表格只在自身容器滚动。
- 确认生成文件不是零字节、标题正确，并且修改时间对应本次生成。

## Linear 附件替换

1. 先生成并验证新的本地 HTML。
2. 上传新附件并回读确认附件已绑定到正确 Issue。
3. 再删除旧的同名 HTML 附件。
4. 最后回读 Issue，确认只保留一份当前 HTML；仅在用户另行要求上传 Markdown 时核对其附件。

不得先删除唯一可用附件后再开始生成或验证新文件。

## 故障处理

发现 HTML 空白或仅显示外壳时：

1. 立即停止上传和批量生成。
2. 检查浏览器 Console 和 HTML 中核心内容是否实际位于 `<body>`。
3. 将客户端运行时渲染改为构建时静态渲染，不只修补单个转义字符。
4. 重新执行静态 DOM、无 JavaScript、脚本语法和响应式检查。
5. 上传新附件、确认成功后删除故障附件，并回读 Linear 验证。
