# 首要交付：HTML 故事视频

**最低交付规则：** 所有类型的 Issue（含 Doc、Research、新人入门、资料阅读与走查）至少交付一份逐 Task 的自包含 HTML 讲解视频；双语按语言分别生成。非开发任务讲清要学什么、做什么、交什么及谁来复核，不虚构产品改动或自动化验收。获授权写入 Linear 后须绑定真实视频附件、下载并核对文件大小与 SHA-256；未完成时不得报告整条 Issue 已完整交付。


## 适用条件

Issue 范围与 Task 确认后默认执行，不要求用户再次点名制作视频。视频 HTML 是最高优先级的评审、预览和附件入口；先完成逐 Task 讲解的视频，再交付静态规格 HTML 作为详细参考。不得因任务类型或粒度自行跳过视频。视频解释已批准的产品意图与用户故事，不替代作为内容源与验证材料的 `issue.md`、`issue.html`、`formalization.lean`。生成默认视频不等于获得 Linear 写入权限：仅在用户授权创建/更新并上传时绑定附件；仅本地、先审阅或暂不上传的要求持续有效。

视频默认是平静、温和、以讲解为主的短片：像一位表达清楚的同事带着同事走一遍这次改动——合成女声旁白、同步字幕、浅色安静画面、缓慢连续的镜头与柔和淡入淡出，以及明显低于人声的温暖钢琴配乐。不追求戏剧化、机械罗列或重复。默认视频按此执行，无需再次询问是否配音；用户指定声音或明确要求无旁白、纯字幕时遵从。TTS 失败时报告缺少人声并保留可重试输入，不能静默交付字幕配乐版并宣称完整。只有用户明确选择无旁白时才使用 `--no-narration`。

## 输入来源

旁白与开场按 [写清现状与具体改动](product-change-writing.md) 按用户需求、遇到的痛点、系统现状介绍背景，再说明目标预期。背景介绍按用户需求、痛点、系统现状讲解，不得只截取首句遗漏后续事实；目标预期说明完成后的用户能力。

只使用已确认规格中的内容：标题、Product/Domain、背景、用户故事、Task 名称、用户流程和非目标。不得在视频中新增功能、承诺、数据或品牌口号；用户额外指定的文案、配色、时长、配乐或配音优先于默认设置。

## 生成与预览

```bash
node scripts/video/create-video.mjs <issue.spec.json> --out <issue-dir>/video --lang zh|en --narration <work>/manifest.json [--theme calm|acid|dusk]
```

- 复制 `assets/html-video/` 并从规格生成 `js/data/story.js`。之后可直接编辑 story：场景顺序、`dur`（秒）、`itemAt`、`layout`、文案、`music`、`mix`、`narration` 与主题均为数据。
- 默认主题 `calm`（`js/data/themes.js`）：浅色暖中性舞台，与 shadcn 风格 UI 画板一致；背景按全局时间缓慢流动、跨场景连续；无粒子、光束、闪烁或切场音效。`acid`、`dusk` 仅在用户明确要求影视/宣传风格时使用（`--theme acid|dusk`），此时才启用 `particles`（`stream`/`converge`/`burst`/`drift`）、`mist`、`beams`、切场冲击/提示音与 `pulse` 节拍配乐。
- 打开方式：`index.html` 使用经典脚本、无 ES Module、无核心代码 `fetch`，可直接以 `file://` 打开。若 `story.js` 引用外部音频文件，`file://` 下浏览器会拒绝读取：运行 `node scripts/video/embed-media.mjs <video-dir> <音频文件…>` 嵌入为 `js/data/media.js`，或在该目录运行 `python3 -m http.server` 后通过 `http://localhost:8000/` 打开。
- 可维护源码是整个文件夹（`index.html`、`css/`、`js/` 与嵌入媒体）；附件交付另由 `standalone-video.mjs` 内联成自包含 HTML。不要直接上传依赖相对路径的 `index.html`，也不要把视频与 PRD `issue.html` 混用。
- 先执行下文合成旁白流程，再生成播放器；只导出 `--script-out` 不需要音频。生成完整视频时，缺少 `--narration` 且未显式选择 `--no-narration` 会报错，禁止用默认无声输出绕过此流程。

## 背景介绍与现状画面

涉及前端的 Task 按 `page-location-evidence.md` 交代所在端、页面及具体板块，再演示该位置的控件和结果；画面可标路由，区分已存在与拟新增，不必逐字朗读路径。规格中已有真实截图时将现状与目标原型明确分开；没有真实截图不生成虚假的现状画面。视频镜头不能把页面范围重新泛化为大方向。

## 时间与音频约束

- 唯一主时钟（`js/core/clock.js`）：时间 = 锚点时间 + (时钟源 − 锚点) × 速率，不累加逐帧增量；音频运行后时钟源切换为 `AudioContext.currentTime`，画面与声音读同一时钟。
- 无时间锚点的链接首次打开或刷新时，播放器暂停在 00:00，进度条与实际时钟均为 0；海报预览时间不得作为播放起点。只有链接显式携带 `#秒数` 时才跳转到该位置。
- 场景、条目出现、旁白片段、音效与配乐都由 `js/core/timeline.js` 从 story 推导。场景时长用 `dur` 秒（旧 story 的 `beats` 仍兼容），条目用 `itemAt` 秒。场景存活区间为 `[start, end)`，仅存活场景的文字层可见；轻微推近、淡入淡出与（影视主题的）粒子都是时间的纯函数，因此可精确 seek、重播并逐帧求值（`HV.debug.renderAt(t)`）。
- 播放、暂停、seek、重播、变速都会递增时钟 epoch，音频调度器停止旧节点并按新映射重排；持续音在 seek 后从中途续播。变速时合成音保持音高，录音片段以 `playbackRate` 变速（音高随之变化）。
- 帧循环被挂起或节流（后台标签页、卡顿）后恢复时，调度器不补播已过期的音效或片段：完全过期的直接丢弃，仍在发声的持续音与录音片段从当前位置（偏移 = 当前时间 − 起点）加入，未来音效保持原定时刻。
- 画面按“可听时间”渲染：输出延迟是音频源秒，换算为主时间需乘以当前速率（`clock.audibleTime(latency)`），因此 0.5×/2× 下画面同样对齐所听到的声音；暂停与逐帧求值不受延迟影响。
- 音频只在用户点击后创建；提供静音按钮、总音量滑块、“音乐”滑块（只调配乐，URL 可用 `?music=0..1`）、字幕开关和键盘快捷键。
- 混音：`story.mix` 设定 `music`/`voice`/`effects` 总线电平（URL `?mix=音乐,人声,音效` 可覆盖）。旁白期间配乐自动压低约 6 dB（起 0.35 s、回 1.1 s），间隔小于 1.8 s 的相邻旁白合并为一个压低区间，避免配乐在句间或场景间忽大忽小。每个调度周期的声音走独立分组增益，暂停/seek/变速时先 40 ms 淡出再停止，避免爆音；中途加入的持续音按已衰减的电平淡入，不重新起音。
- 旁白：每条 `narration` 有 `scene`、`at`、`dur`、`text`、音频 `src` 与逐句字幕 `cues`，默认生成对应语言的合成女声；也可使用用户提供并有权使用的录音。仅明确选择无旁白时 `src` 为空、字幕承载文本，并在 `voiceNote` 说明“无人声”。合成语音必须标注为合成，不冒充真人录音；不做声音克隆，不使用需要账号、付费或凭据的服务，不复制他人项目内嵌的授权语音。

## 默认配乐

- 默认 `music.style: "warm"`（`js/audio/score.js`）：F 大调 I–vi–IV–V，每个和弦两小节、72 bpm，稳定主音中心；近距离声部进行的钢琴分解和弦（加性正弦泛音、无失谐、自然衰减、换和弦时制音、同音重击时先止前音），一层很轻的纯正弦铺底，开头只有铺底与低音缓慢进入，结尾在主和弦上自然余响。音乐按全局小节网格排布，不随场景切换重置，Task 之间不会跳变。
- 不使用：不协和琶音、阴郁小调张力、失谐拍频/相位摇摆、持续嗡鸣、过量混响、刺耳高音、底鼓/镲/拍手、切场冲击与“嗖”声。`pulse` 旧节拍配乐只随明确要求的影视主题使用。
- 可改 `story.music`（`bpm`、`root`、`progression` 级数如 `["I","IV","vi","V"]`、`chordBars`、`pattern`）与 `story.mix`；若用户提供有权再分发的录音，用 `music.src` + `embed-media.mjs` 离线打包，并记录许可；不复制其他项目的授权音频，不接入付费服务。
- 检查配乐时，离线渲染（同一引擎）确认无削波、无爆音、旁白期间配乐约低于人声 10 dB、场景切换处不断音，并提供一段可直接播放的混音样例；信号指标不等于“好听”，未实际试听须如实说明。

## 预览与 MP4 的区别

浏览器预览是交互式 HTML；MP4 是另一种交付物，需要逐帧调用 `HV.debug.renderAt(t)` 截图并离线渲染音频后编码。未实际编码并检查 MP4 的音画同步与听感时，只能报告“提供 HTML 预览”，不得声称已导出 MP4 或已完成音频质检。

## 检查

- `node --test scripts/video/*.test.mjs`：覆盖无旁白构建拦截、明确选择无旁白、媒体打包、字幕边界、场景边界、场景时长来自实测旁白而非节拍、条目在被说到之前出现、粒子不越过揭示前沿（影视主题）、seek 顺序无关、时钟无漂移、音频窗口无漏无重、默认配乐跨切场连续/调内/以主和弦结束且无切场音效、旁白必须落在所属场景内；帧循环停顿后不补播过期音效、持续音与片段以正确偏移加入（含 2×）、延迟按速率换算、压低区间合并、停止前分组淡出。
- 验证外部音频路径时使用明确标注的生成测试音（例如扫频正弦），不要用人声冒充旁白验证；`HV.debug.audio.taps.voice`（旁白总线上的 AnalyserNode）与 `clipStarts()` 可用于测量解码、偏移和速率。信号测量不等于试听。
- 浏览器中确认：无 Console error；点击前无 AudioContext；暂停时间冻结；seek 跨场景后只有一个场景可见；2× 速率与音频时钟一致；重播回到开头；结束显示 Replay。
- 若无法实际收听，说明听感未验证；信号级检查（离线渲染非静音、未削波）不等于听感质检。
- 有声版必须等待 `HV.debug.audio.state().voiceClips` 等于实际旁白片段数，确认每段可解码；在开场和每个 Task 章节测量 `taps.voice` 的非静音信号，不能用配乐总线或测试音代替人声通过。检查 seek、暂停、重播、倍速后人声仍按同一时钟调度。
- 尝试试听开场、各 Task 和切换位置，检查可懂度、专有名词读音、字幕与镜头关系以及配乐是否盖住人声；记录实际试听范围。无法收听或未听完时如实记录，不把自动信号检查称为听审。

## 逐 Task 讲解与双语版本

- 生成器固定输出：开场、背景、用户故事、任务总览（全部 Task ID、完整名称与点数）、每个 Task 一个独立章节（ID、名称、已批准 `items` 与关联 AC Summary）、用户流程、结果、结尾。支持 1–4 个 Task；章节导航与旁白按同一顺序覆盖每个 Task。
- 节奏由旁白决定：场景时长 = 淡入后的起声留白 + MP3 实测时长 + 呼吸留白（段落收尾处稍长），任务画面再按最后一个镜头的信息量保证足够阅读时间；不对齐节拍、不使用统一时长。条目在旁白说到它之前约 0.35 s 出现（按提供方句子边界插值），不会在该句讲完之后才出现。
- 旁白模板在 `scripts/video/story-text.mjs`，语气平静温和，用“先看…”“接下来是…”“验收的时候，我们还会确认…”等自然连接词串联已批准短语（短语原样保留，镜头锚点依赖它），同一事实只说一次，不做“第一项…这一项包括：”式机械罗列：与 Task 范围条目语义重复的 AC 不再朗读也不再上屏（按规格中所有语言共同判断，中英一致），只补充带来新行为的 AC。不新增功能、结果、期限或承诺。
- 需要人工润色时用 `--overrides <reviewed.json>`（`{"场景 id": "文本"}`）：未知场景、缺少 Task ID / 完整名称、总览未按顺序列出全部 Task 时直接报错；改动文本后必须重新生成对应语音。
- 每个场景带安静文字区（`quiet`）：影视主题下区内粒子降到 6% 透明度、光束被裁掉；默认 `calm` 不绘制粒子。Task 左侧逐条显示当前讲解项，避免未讲到的长段落撑高布局；字幕放在舞台外的下方独立区域，不覆盖画板。
- 一种语言一个视频文件夹：`--lang zh|en` 同时本地化画面文案、控件、海报与说明；用 `--alt <另一语言 index.html>` 互相链接。不要在一个视频里叠放两种语言旁白。

## 合成女声旁白（默认流程）

1. 确认旁白只串联已批准事实，读起来连贯，避免机械重复和双重否定；需要润色时先准备 `--overrides`。`node scripts/video/create-video.mjs <spec> --lang zh --script-out <work>/zh/script.json [--overrides <reviewed.json>]`，后续最终构建必须使用同一份 overrides。
2. 在任务本地虚拟环境安装 edge-tts（不全局安装），先列出可用音色并确认为女声；默认 `zh-CN-XiaoxiaoNeural`（Warm）与 `en-US-AvaNeural`（Caring/Pleasant，对话风格）。然后 `<venv>/bin/python scripts/video/narrate.py <script.json> --out <work>/zh [--voice <音色>]`，默认正常语速；平静感来自文案与场景留白，不要整体放慢语速来“装作平静”。脚本有限重试，连续失败即停止并报告原因；系统自带语音只能作为明确标注的低质量后备。
3. `node scripts/video/create-video.mjs <spec> --lang zh --out <video-dir> --narration <work>/zh/manifest.json --alt ../video-en/index.html [--overrides <reviewed.json>]`：先整体校验清单——语言一致、每个场景恰好一段、无多余或重复片段、文本与当前脚本一致（旧版本文本即判为过期）、音频可解析；任何一项不符都拒绝输出，不会静默退回无声片段。之后按 MP3 实测时长加呼吸留白确定场景长度（以秒计，不对齐小节），逐句字幕来自 TTS 提供方的句子边界，媒体内嵌进 `js/data/media.js`，`file://` 可直接播放，运行时不联网。
- 句子时间保留提供方起点；把句尾截到下一句起点和实测音频结束之间，消除提供方约 50 ms 的相邻句重叠。字幕和镜头都使用同一份归一化 cues；句内切短字幕只能在原句区间内插值，不能独立重估整段时间。
- 工作目录放在当前项目 `docs/` 下，生成的音频、清单与虚拟环境不放进技能源码，虚拟环境加入本地忽略规则。生成器在播放器 `media/` 下保留所有音频和含实测时长的 `manifest.json`；交付链接至少包含一个可单独播放的 MP3 样例，并注明合成声音来源。没有实际试听时只报告信号检查结果。
- 仅在用户要求 ZIP 时，最后打包两种语言的完整文件夹，核对归档内的 `story.js`、`media.js`、MP3 与 manifest 和当前文件一致，防止页面有声而下载包仍是旧无声版。

## 上传 Linear（视频验证且写入获授权后）

1. 用当前 Workspace 的 Linear 工具回读目标 Issue 与附件，确认 ID；保留规格正文、属性和三份原附件。仅本地评审时不要求存在 Linear ID，也不为视频创建或改动 Issue。需要上传而无法确定目标 Issue 时再补充该信息，不创建新 Issue 代替。
2. 每种已生成语言执行 `node scripts/video/standalone-video.mjs <video-dir> --out <issue-dir>/cod-<number>-video-<lang>.html`，内联 CSS、经典脚本、音频和画面。PDF 与 MP4 均需用户另行明确要求，不作为 HTML 上传前置步骤。脚本拒绝未嵌入的音频及 CSS 外链，关闭下载后失效的兄弟目录语言链接。默认仅交付每种语言一个自包含 HTML；完整源码文件夹保留在本地，只有用户要求源码包或 ZIP 时才打包并上传，归档须包含许可文件。
3. 用浏览器打开导出的单文件，在不访问外部资源时确认画面、全部人声解码、播放/暂停/seek 和旁白总线信号。打包文件、源文件与最终上传字节必须来自同一验证版本。
4. 每个文件串行执行 `prepare_attachment_upload` → 按原样发送全部签名 headers、PUT 原始字节 → `create_attachment_from_upload` → `get_attachment` 回读。HTML 用 `text/html`，ZIP 用 `application/zip`；不要把大文件转成模型可见的 base64，不批量申请短时效上传地址。失败时有限重试，报告未完成的文件。
5. 下载回读附件并核对大小和 SHA-256，再读取 Issue 确认绑定正确、每个新文件只有一个当前附件。替换同名文件时先确认新附件，再移除旧链接；不删除其他附件。保存附件 ID、文件名、大小和哈希到本地验证报告，最终返回 Issue 链接与上传结果。只有本地生成不能称为已上传。

Linear 支持文件上传与 Resources 附件；HTML 作为可下载文件交付，不能据此宣称 Linear 会托管或在 Issue 内运行该播放器。说明“下载 HTML 后在浏览器打开；ZIP 解压后打开 index.html”。未实测时不承诺内联播放；HTML 不是 MP4。需要原生视频预览时另行执行实际视频编码和验证。

## Task 画面：前端界面 / 后端流程

每个前端 Task 展示对应的已批准页面、Dialog、Drawer 或状态；后端 Task 展示业务处理流程；混合 Task 按讲解顺序切换两者。引用 `spec.components` 与结构化 Flow Schema，不新增界面、实现架构、功能或分支。配置前先确认 Task 与组件/流程的关联，不能只按名称猜测。无已批准画面时先补规格，不用无关插画冒充实现。

在规格中添加可选 `video`，结构示例见 `assets/issue-html/example.spec.json`：

```json
{"video":{"tasks":{
  "T1":{"kind":"frontend","shots":[{"component":"channel-list","on":{"scope":0}}]},
  "T2":{"kind":"backend","shots":[{"flow":"channel-save","on":{"scope":0}}]},
  "T3":{"kind":"mixed","shots":[{"component":"add-channel-custom","on":{"scope":0}},{"flow":"channel-save","on":{"scope":1}}]}
},"flows":[{"id":"channel-save","direction":"TB","nodes":[],"edges":[]}]}}
```

- 上例 `nodes/edges` 只是结构示意；实际必须提供通过 `flow-diagram-schema.md` 校验的完整节点、双语标签与分支。流程引用 `video.flows` 或现有 `spec.flow`。两种语言共用同一绑定、节点与边；显示名称可用 `flow.name.zh/en`。
- `on.scope` 是该 Task `items` 的零起点索引，也可用 `on.ac` 引用本 Task 的 AC ID。短语必须仍出现在实际旁白中，且后续镜头顺序与旁白顺序相同；已去重的 AC 或人工改写掉的短语不能作为锚点，应更换对应锚点。首张画面从 Task 开头出现，其余镜头按旁白位置切换。
- `kind` 为 `frontend`、`backend`、`mixed`；一旦提供 `video.tasks`，必须覆盖所有 Task。类型不符、未知 Task/组件/流程、缺失短语、流程无效时拒绝生成。旧规格不带 `video` 时保留文字讲解，明确没有相关界面演示。
- 前端画面复用 PRD 静态原型渲染器与 CSS（shadcn 风格产品 UI 层），在禁止脚本/联网的沙箱里展示；这是规格示意，不代表真实功能已经实现。后端流程通过 Graphviz `dot` 自动布局（默认浅色节点，成功/错误节点用语义色描边；影视主题用深色），构建环境需已安装 Graphviz，缺失则停止；播放不需要它。SVG 与 Mermaid 从同一 Schema 生成，保存在视频 `visuals/`，播放使用内嵌 SVG，离线可用。
- 镜头切换来自同一主时间轴。优先使用配音提供方的句子边界，句内按文本位置估算（`sentence-interpolation`）；无语音则按文本长度估算（`estimated-text`）。不能宣称是逐字精确对轴。人工试听后可审阅数据调整时点，但不引入独立计时器。
- 验收逐个 Task 的每个镜头：内容对应已批准规格、前端按钮/表单/错误完整、流程各节点与分支清晰、中英文一致、字幕不遮挡、暂停/seek/重播/变速后镜头正确。至少检查桌面与窄屏，不能只检查 DOM 里存在画面。
