# 标题与正文来源

## 唯一正文来源

读取同级 forge--linear--show-issue-best-practice 的 references/issue-contract.json 和 references/standard.md。机器字段、必填、章节、映射以契约为准，业务写法依标准。打开表单用 forge--linear--show-issue-form，审查用 forge--linear--review-issue。

先填写当前表单 JSON，再运行本技能 scripts/assemble-issue.mjs。标题写标题栏，项目、负责人、优先级、状态及点数写原生 Properties；description 必须与生成的 issue.md 完全相同，从摘要开始，不重复基本信息。

保留摘要的做什么／从哪开始／怎样算完成。背景自由带原话及截图，不设固定“甲方原始意见与截图”章。Task 用做什么及输入／预期输出验收条件。其他正文只由表单映射，不再维护手工 Markdown 模板。

## 标题

### 先对齐同项目，再写清用户诉求

先核对角色是否为已确认岗位或人员身份，不从功能名推导岗位；未知具体岗位时使用已知身份，将系统权限写进操作前提。

创建前读取同项目、同模块的几条相关 Issue，核对真实的分类、角色称呼与标题格式；不能只照抄标签顺序。用户已确认的格式优先，历史标题中的含糊表达不作为新标题的依据。

默认格式：

- `zh-CN`：`[<Module>][<Type>] 作为<具体角色>，我希望通过<具体入口或业务操作>，可以<可观察的业务结果>`
- `zh-en`：`[<Module>][<Type>] 作为<具体角色>，我希望通过<具体入口或业务操作>，可以<可观察的业务结果> ｜ As a <specific role>, I want to use <the same entry point or business action> so that I can <the same observable business outcome>`
- 跨模块工程改进使用 `[Opt]`，不添加伪模块；模块内功能、缺陷和优化分别使用 `[Module][Feature]`、`[Module][Bug]`、`[Module][Opt]`。
- 分类前缀只出现一次，后面留一个空格；双语使用一个全角 `｜` 分隔，分隔符两侧空格按同项目已确认的格式保持一致。

### 角色、操作途径与结果都要具体

- 中文标题统一使用“作为……，我希望通过……，可以……”。三部分分别说明具体角色、可识别的产品入口或业务操作、可验收的业务结果；不能省略“通过”或“可以”。
- “通过”写用户实际使用的页面、控件或业务动作，不写 Service、数据库或代码路径；“可以”写完成后的具体能力，不用“提升效率”“优化体验”等空泛收益。
- 保留 `[Module][Type]` 分类前缀。标题格式改变不增加 Task、估点或功能承诺。
- 点名实际业务对象及关键条件，例如“查询色号”“连续发送两张图片”“刷新用户会话”。避免“这个功能”“相关内容”“优化体验”“打通链路”等无法判断范围的表达。
- Bug 标题写用户希望恢复的正确行为，必要时包含触发条件；不能只有“修复异常”或没有结果的“不对”“不稳定”。
- 使用用户能理解的结果，而非提交摘要或实现方案。工具函数名、服务拆分、技术字段和文件路径通常放在正文；“按需收到对应色卡”比“拆分 query 与图片 tool”清楚。
- 英文对应使用 `As a/an …, I want to use … so that I can …`，保留中文的角色、操作途径和结果；不得只写 `Fix…`、`Keep…`、`Add…` 等祈使句，也不扩大或缩小中文范围。
- 每条标题聚焦一个可验收结果。紧密相关的必要行为可合写；无关目标回到范围拆分，不用长串“并且”堆进标题。详细规则、验收条件及完整收益放正文，不为缩短标题删掉关键场景或对象。

### 正反例

以下为写法示例，不代表已核实的项目事实或授权创建事项。

| 不清楚或格式不一致 | 改成 | 原因 |
|---|---|---|
| `[Glossary][Feature] 维护黑话库` | `[Glossary][Feature] 作为汉高员工，我希望通过后台黑话库，可以维护和检索汉高黑话词条` | 角色、操作入口和结果完整，功能范围清楚。 |
| `[Transcript][Feature] 作为汉高员工，我希望校订错词` | `[Transcript][Feature] 作为汉高员工，我希望通过逐段文字校订，可以修正会议转写并对照原始识别文字` | 说明通过什么操作完成什么，结果可以验收。 |
| `[Agent][Opt] 优化会话体验` | `[Agent][Opt] 作为后台管理员，我希望通过会话列表的用户筛选，可以查看指定用户的会话 ｜ As an admin, I want to use the user filter in the session list so that I can view a specific user's sessions` | 双语均表达同一角色、操作途径和业务结果。 |

提交前将标题脱离正文单独读一遍：若还需追问“谁用、通过什么、可以完成什么”，应重写。再核对同项目格式和中英文含义；全部成立后才定稿。
