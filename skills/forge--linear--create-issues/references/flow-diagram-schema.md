# 业务流程图 Schema 规范

## 目标

复杂业务流程必须先定义结构化 Flow Schema，再由成熟图布局引擎生成 Mermaid 与 HTML SVG。Schema 是节点、分支和业务结果的唯一来源，页面代码不得自行推断或重新编排流程。

## 先确定真实业务路径

先列明这条需求的业务对象、入口、操作、状态和用户结果，再定义节点。不同业务不得套用同一张通用编辑校验图。实体管理图应表达列表、详情及新增/编辑/启停后去向；会议校订图应表达会议选择、段落校订、原文对照以及主动重新整理纪要的关系。只纳入实际 Task、交互或 AC 已定义的分支，不为图的完整性新增功能。

## 最小结构

Flow Schema 必须包含：

- `id`：稳定且唯一的流程标识。
- `direction`：`TB` 或 `LR`。
- `nodes`：流程节点列表。
- `edges`：节点之间的有向关系。

每个节点必须包含稳定 `id`、受支持的 `kind`，以及当前语言模式需要的文案：`zh-CN` 只要求 `zh`，`zh-en` 要求语义一致的 `zh` 与 `en`。推荐的节点类型为：

- `start`：用户行为或业务事件起点。
- `process`：用户操作或产品处理阶段。
- `decision`：会产生不同后续路径的业务判断。
- `source`：规则来源或优先级解析结果。
- `success`：成功结果。
- `error`：失败或阻断结果。
- `finish`：用户可感知的最终状态。

每条边必须声明 `from` 与 `to`。存在业务含义的分支边必须提供当前语言模式需要的标签；`zh-en` 标签必须语义一致。

## 强制校验

生成流程图前必须验证：

- 节点 ID 格式合法且不重复。
- 节点类型属于允许集合。
- 所有节点均有当前语言模式要求的文案。
- 每条边引用的起点和终点均存在，且不存在自连接。
- 分支标签具有当前语言模式要求的文案。
- 流程仅有一个起点，且所有节点均可从起点到达。
- 起点来自用户行为或业务事件，终点是用户可观察的产品结果。
- 节点和分支可追溯到正文中的用户流程、行为条件、Task 或验收标准。

校验失败时停止生成，不得以手工修改 SVG、HTML 或 CSS 的方式绕过。

## 输出规则

- Markdown Mermaid 与 HTML SVG 必须由同一份 Flow Schema 生成。
- HTML 图必须使用 Mermaid、Graphviz 或等价的成熟自动布局引擎。
- SVG 必须自包含并保留可访问名称；窄屏允许图表容器局部横向滚动，但页面本身不得横向溢出。
- `zh-CN` 只生成中文图；`zh-en` 的中文图和英文图必须拥有相同的节点 ID、节点类型、边和分支，仅展示文案不同。
- 生成结果不得增加 Schema 中不存在的页面、角色、状态或结果。

## 禁止方式

- 不使用绝对定位、伪元素边框、字符箭头或固定像素坐标手工拼接流程线。
- 不分别维护两份独立 Mermaid、SVG 或 HTML 流程定义。
- 不在产物中展示数据库表、字段、Service、API、文件、队列或实现调用链。
- 不为了视觉对称合并、删除或改写产品分支。
