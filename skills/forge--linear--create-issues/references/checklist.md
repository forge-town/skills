# 创建 Linear Issue 完成清单

- [ ] 已核对真实项目、既有事项与写入授权（例：避免同目标重复创建）。
- [ ] 已读取唯一最佳实践和契约，选择准确表单类型（例：不假选执行方式，不虚构入口）。
- [ ] 已在表单中保留三项摘要、具体 Task 和输入输出验收条件（反例：手写一份“符合表单”的正文）。
- [ ] 已核对事实、未解决条件和原生属性映射（例：未知值不清空原属性）。
- [ ] 已由 assemble-issue 生成，并用 --form 严格验证正文一致（例：多加一句也需回到表单修改）。
- [ ] 已完成适用附件及独立验证，或明确未完成（例：普通静态 HTML 不冒充视频）。
- [ ] 已按授权最小写入并回读正文、属性及适用附件（反例：接口返回成功就宣称完整交付）。
- [ ] 已返回真实链接与全部缺口，未把规格完成称为产品验收通过（例：待 reviewer 复核仍为 In Review）。

- [ ] 已读取当前项目模块负责人绑定并核对有效用户；创建请求填写原生 Assignee，回读人员一致。用户明确指定优先，缺失或冲突不猜测，只本地 review 不线上分配。

- [ ] 人物在 Linear description 中为标准 Markdown 斜体，没有生成的 HTML 标签；标题与原生属性保持纯文本。
