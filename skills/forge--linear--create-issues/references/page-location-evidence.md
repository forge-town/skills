# 操作位置与现状材料

## 在任务中写清操作位置

不生成独立的“页面定位 / Page Locations”章节或定位表。必要的端、页面、板块和入口信息直接写进 Task 首段与操作入口说明；不要重复列一份页面清单。

- 核查现有入口和页面，区分已有功能与拟新增功能，不凭名称猜路由。
- Task 直接写清在哪个板块添加或修改什么，操作后出现什么结果。
- 必要的路由或源码定位放在Task 和操作说明（源码定位仅留本地核查记录）中，不为满足模板预先规定尚未确定的路由。
- 弹窗、抽屉说明触发控件与完成后的去向，不给没有独立页面的组件编造 URL。
- Task、操作说明和 AC 对同一页面、控件与结果使用一致名称。

## 背景介绍中的系统现状

涉及现有 UI 的问题或改进，默认尝试取得关键现状截图。优先使用用户标注截图或可访问的真实页面；截图应体现具体缺口，不能只有无关整页或登录页。

每张图使用稳定证据 ID（例如 S1），记录：所属端 / 页面、实际 URL 或路由、环境、观察角色、采集时间或来源、图中问题位置，以及它支持的那一句现状。裁剪和编号标注可用于定位，保留必要上下文。

正文“背景介绍”依次说明：

1. 具体角色的业务需求：想在什么场景完成什么。
2. 当前操作中的痛点：在哪一步受阻及已知影响。
3. 系统现状：已有能力与缺口；有真实截图时将图片和图注放在此处。

完成后的用户能力写入独立“目标预期”，不在背景介绍中提前展开功能设计。无法取得截图时在本地核查记录中说明原因，不另建“现状与截图”章节。

取证要求：

- 当前页面截图、会议视频帧、代码检查和方案原型是不同来源，必须分别标明。会议帧附会议链接与时间点；旧截图不能当作线上当前版本。
- 新页面尚不存在时，截图取相关现有页面或导航，说明当前已有路径与缺口；不为新页伪造“现状截图”。
- 无法访问页面、没有对应角色或浏览器工具拒绝访问时，写清“现状截图待补”及具体原因；可继续写有依据的范围，但不能宣称画面已核实，不绕过工具限制。纯后台需求写明不涉及页面截图。
- 保留必要业务上下文，遮盖截图中的敏感个人信息；说明处理，不更改证明问题的字段或行为。
- 本地截图放在该 Issue 目录的 `evidence/` 下，目录本身位于项目 `docs/`；正文用 S1 等 ID 引用，避免重命名后失联。

## 产物保留必要现状说明

- Linear 正文、`issue.md` 和 `issue.html` 不生成独立页面定位章节或表格；必要的操作位置写进 Task 和操作说明，现状说明按实际内容保留。已有真实截图时应在 Linear 正文内引用可访问的图片资源，HTML 中嵌入图片字节并附图注；不能只给本地图片路径或在最终答复贴图。
- 截图原图可作为补充图片附件逐个上传并回读，作为默认 HTML-only 的证据例外；不因此上传 Markdown、Lean、PDF 或额外归档。必要时先创建正文，再绑定图片资源、补回正文引用并重新生成与核对 HTML。
- 初稿尚无可访问图片资源时保留证据 ID 与“截图待补”，不能向 Linear 写入 `file://`、本地路径、过期签名下载 URL 或 Base64 字符串充当图片链接。
- 检查图片确实解码可读，放大后能看清目标位置；Markdown 图片、HTML 图注与证据 ID 一一对应。未取得真实截图时，不用静态原型、示意图或 ImageGen 补位。
- 使用生成器时确认其实际支持定位与截图内容；不支持的部分需补齐生成器或静态呈现，并验证重建不丢失，不能塞进未知字段后假定会显示。
- 默认讲解视频中，相关 Task 先交代端、页面、板块与操作位置，再演示行为；路由显示在画面定位标签即可，不必逐字朗读。只使用规格内已核验截图，注明现状，和目标原型分开呈现。
- 收集截图、整理路由和规格排版属于需求说明，不独立创建 Task、加点或扩张产品范围。

## 交付前的直接判断

把 Issue 单独交给另一位开发或测试：他能否不追问“放哪儿”，直接找到端、入口、页面、路由、板块、控件、现状证据和操作后去向？缺少其中适用项就补具体；不要以“按现有风格”“类似某模块”“核对无误”代替。
