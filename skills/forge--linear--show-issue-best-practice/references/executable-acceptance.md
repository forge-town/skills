# 验收案例写法

每个案例对应一个任务，按“前提条件／操作／预期结果”组织，界面和正文只使用中文。

- 前提条件：当前必要状态与具体样例；仅当权限影响结果时写角色，不强制补账号、组织或环境地址。
- 操作：写清用户操作的控件和具体输入，多轮场景逐步展开；只写一套，不再附步骤表。
- 预期结果：给出可观察的文字、字段值、状态或行为，不能只写“正常”“成功”。

不设置执行方式、完整执行入口、执行账号与组织、清理恢复或未解决的执行条件；不因缺这些字段阻断生成，不加完成条件章。不要把删除的字段改名塞回案例或检查报告。必要业务前提写进前提条件，未知事实不编造。

案例的正反分类和任务关联保留；每个任务有正面案例，必要异常和边界用反面案例表达。Bugfix 可单独记录真实执行结果和证据；案例预期不代表已测试通过。

完整例子见 [Todo List](../best-practice-examples/todo-feature.json) 和 [类幸存者](../best-practice-examples/survivors-feature.json)，表单 Header 可以查看并打开对应原型。
