# Bugfix 完整示例：清空搜索后未恢复列表

两类表单都保留摘要：做什么／从哪开始／怎样算完成。完整 JSON 中已填写这三项。表单中摘要在基本信息之后；生成的正文从摘要开始，标题和基本信息只放 Linear 原生字段。

[Bugfix 示例 JSON](bugfix-example.json) 可直接导入 Bugfix 表单。它是虚构的教学问题，引用 [Feature 示例](issue-example.json) 的演示约定，不表示真实产品存在该缺陷或已经修复。频率如实标为“暂未复现”，根因留空，全部验收案例为“未执行”。

- 复现：三条任务已载入，输入“登录”，再清空。
- 实际现象：整理的问题描述中，清空后仍只有 A、C；未在真实产品复测。
- 预期：空关键词应显示 A、B、C；依据是 Feature 演示的 BR-01。
- 修复范围：恢复清空行为，保留现有标题筛选；不新增全文搜索。
- BR-01：清空关键词恢复全部；AC-01 正面案例核对 A、B、C。
- BR-02：非空关键词按标题筛选；AC-02 正面案例核对 A、C。
- AC-03 反面案例：先触发无匹配，再清空，关联 BR-01，核对恢复全部。

错误写法：“搜索出 Bug 了，修好就行，根因是缓存。”没有复现与对照依据，且把未核实的猜测当根因。

正确写法：描述环境、前提、输入、逐步操作、实际与预期及预期依据；根因未知留空，提供可执行排查起点，再写抽象业务规则和关联的具体验收案例。

本例通过前端“导入 JSON”载入；或者用打开脚本 --type Bugfix --input 指向本 JSON。Header“查看示例”现只展示两个具体 Feature 场景。Bugfix 同样填写 BR 和正反验收案例；不要求补 Feature 的用户故事或功能概览。
