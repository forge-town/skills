# 自动发现机制指南

此指南详细说明check-all-items技能如何自动扫描和发现本地技能库中的最佳实践技能。

## 发现机制概述

自动发现机制通过扫描技能库目录，识别所有符合命名规范的技能，无需手动配置或维护列表。

## 命名规范

### 技能名称要求
- 必须以 `best-practice` 结尾
- 使用连字符分隔格式（kebab-case）
- 示例：
  - `dao-best-practice`
  - `service-best-practice`
  - `store-best-practice`
  - `page-best-practice`

### 目录结构
```
skills/
├── dao-best-practice/
├── service-best-practice/
├── store-best-practice/
└── check-all-items/
```

## 扫描过程

### 1. 目录扫描
- 扫描 `skills/` 目录下的所有子目录
- 识别包含 `SKILL.md` 文件的有效技能目录
- 跳过不符合规范的目录

### 2. 技能验证
- 读取每个候选技能的 `SKILL.md` 文件
- 验证YAML前言格式
- 确认技能名称以 `best-practice` 结尾
- 检查技能描述和功能完整性

### 3. 技能注册
- 将验证通过的技能添加到执行列表
- 记录技能的基本信息（名称、描述、路径）
- 按预定义优先级排序

## 执行优先级

### 默认执行顺序
1. `dao-best-practice` - 数据访问层检查
2. `service-best-practice` - 业务逻辑层检查
3. `store-best-practice` - 状态管理检查
4. 其他best-practice技能（按名称字母顺序）

### 自定义优先级
可以通过配置覆盖默认执行顺序，确保依赖关系正确。

## 错误处理

### 技能发现失败
- **原因**：SKILL.md文件缺失或格式错误
- **处理**：记录警告，继续扫描其他技能
- **报告**：在最终报告中列出发现失败的技能

### 命名规范不符
- **原因**：技能名称不符合 `*-best-practice` 格式
- **处理**：跳过该技能，不包含在执行列表中
- **报告**：记录跳过的技能及其原因

## 性能优化

### 缓存机制
- 缓存技能发现结果，避免重复扫描
- 在技能库变更时自动刷新缓存
- 支持强制刷新选项

### 并行执行
- 支持并发执行多个最佳实践检查
- 控制并发数量避免资源过载
- 智能调度考虑技能间的依赖关系

## 扩展性设计

### 新技能自动发现
- 新增的best-practice技能会自动被发现
- 无需修改check-all-items的配置
- 支持热加载新技能

### 技能分类
- 支持按类型分组best-practice技能
- 允许选择性执行特定类型的检查
- 提供分类统计和报告

## 调试和监控

### 详细日志
- 记录扫描过程的每个步骤
- 显示发现的技能数量和状态
- 报告跳过或失败的技能

### 监控指标
- 扫描耗时
- 发现技能数量
- 执行成功率
- 平均检查时间

## 配置选项

### 扫描范围
```yaml
discovery:
  include_patterns:
    - "*-best-practice"
  exclude_patterns:
    - "test-*"
  scan_depth: 2
```

### 执行控制
```yaml
execution:
  parallel_limit: 3
  timeout_seconds: 300
  retry_attempts: 2
```

## 故障排除

### 常见问题

**Q: 为什么我的best-practice技能没有被发现？**
A: 检查技能名称是否严格以"best-practice"结尾，SKILL.md文件是否存在且格式正确。

**Q: 扫描速度太慢怎么办？**
A: 启用缓存机制，或调整并行执行限制。

**Q: 如何排除某些技能？**
A: 使用exclude_patterns配置，或重命名技能使其不符合命名规范。

## 最佳实践

### 技能命名
- 始终使用 `*-best-practice` 格式
- 选择描述性的前缀（如功能领域）
- 保持名称简洁明了

### 技能组织
- 将相关技能放在逻辑分组中
- 为复杂项目创建专门的最佳实践技能
- 定期审查和清理过时的技能

### 性能调优
- 监控扫描性能
- 合理设置超时时间
- 使用缓存减少重复工作
