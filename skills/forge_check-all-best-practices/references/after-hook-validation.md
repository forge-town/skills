# After Hook验证机制

此文档详细说明 forge_check-all-items 技能的强制验证机制，确保所有最佳实践检查完成后执行标准化校验指令。

## 机制概述

After Hook验证机制在所有最佳实践检查完成后自动触发，强制执行预定义的验证指令，确保输出结果的一致性和稳定性。

## 设计原则

### 强制执行
- **不可跳过**：所有检查完成后必须执行验证
- **标准化**：使用统一的验证指令和标准
- **自动化**：无需人工干预，系统自动触发

### 错误阻断
- **失败阻断**：验证失败时阻断后续流程
- **详细报告**：提供具体的失败原因和修复建议
- **可重试**：支持自动重试失败的验证

## 验证指令

### 默认指令
```bash
npm run quality
```

### 指令组成
- **质量检查**：代码质量、类型检查、格式化
- **测试执行**：单元测试、集成测试
- **静态分析**：ESLint、Prettier、TypeScript编译

### 自定义指令
支持项目特定的验证指令：

```yaml
validation:
  command: "npm run quality && npm run test:unit"
  timeout: 300
  retry_count: 2
```

## 执行流程

### 1. 检查完成触发
- 所有技能检查完成后统一触发验证

### 2. 指令执行
- 在项目根目录执行验证命令
- 捕获命令输出和退出码
- 记录执行时间和结果

### 3. 结果处理
- **成功**：继续后续流程
- **失败**：记录详细错误信息
- **超时**：终止执行，标记为失败

## 输出格式

### 成功报告
```
✅ 验证通过
执行时间: 45秒
检查项目: 代码质量, 类型检查, 单元测试
```

### 失败报告
```
❌ 验证失败
错误详情:
- ESLint: 发现3个错误
- TypeScript: 编译失败
- 测试: 2个测试用例失败

修复建议:
1. 运行 `npm run lint:fix` 自动修复ESLint错误
2. 检查类型错误并修复
3. 运行 `npm run test` 查看详细测试结果
```

## 配置选项

### 验证级别
```yaml
validation:
  level: "strict"  # strict, normal, relaxed
  fail_fast: true  # 遇到第一个错误即停止
  verbose: true    # 详细输出
```

### 超时设置
```yaml
validation:
  timeout_seconds: 300
  retry_attempts: 2
  retry_delay_seconds: 5
```

### 条件执行
```yaml
validation:
  run_after_all_checks: true  # 仅在所有检查完成后执行一次
  skip_on_network_error: false  # 网络错误时跳过
```

## 错误处理

### 常见错误类型

#### 命令执行失败
- **原因**：验证脚本不存在或执行错误
- **处理**：检查package.json中的脚本定义
- **修复**：确保项目配置正确

#### 超时错误
- **原因**：验证过程耗时过长
- **处理**：增加超时时间或优化验证脚本
- **修复**：检查系统资源和网络连接

#### 依赖缺失
- **原因**：验证工具未安装
- **处理**：自动安装缺失依赖
- **修复**：运行 `npm install` 或等效命令

### 重试机制
- **指数退避**：失败后延迟重试
- **最大重试次数**：避免无限重试
- **不同策略**：每次重试使用不同参数
