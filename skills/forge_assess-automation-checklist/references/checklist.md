# Plan Check Script 执行确认清单

执行规则：**设计方案完成后逐项确认**

---

## 一、Checklist 理解

- [ ] 已完整阅读目标 checklist 的所有规则
- [ ] 已理解每条规则的**判断标准**（什么算通过、什么算失败）
- [ ] 已标注规则的**模糊边界**（存在灰色地带的项）

---

## 二、脚本化评估

- [ ] 每条规则都有明确的脚本化判定（✅/❌/⚠️）
- [ ] 可脚本化规则有技术实现路径（AST/正则/文件系统）
- [ ] 混合策略规则明确了脚本和 LLM 的分工边界
- [ ] 不可脚本化规则有明确理由说明

---

## 三、技术方案

- [ ] 已选定 AST 解析方案（如有需要）
- [ ] 已确定文件扫描范围（包含/排除模式）
- [ ] 已设计输出格式（机器可读）
- [ ] 已评估性能（大型项目的扫描时间预估）

---

## 四、实施规划

- [ ] 规则已实现优先级排序（P0/P1/P2）
- [ ] 已识别规则间的依赖关系
- [ ] 已估算各规则的实现成本
- [ ] 已确定 MVP（最小可用脚本）包含哪些规则

---

## Bad Case 确认（不得出现）

- [ ] ❌ 方案中包含无法实现的规则（误判为可脚本化）
- [ ] ❌ 技术选型与项目技术栈不匹配
- [ ] ❌ 方案中只有规则列表，无技术实现细节
- [ ] ❌ 未明确区分脚本和 LLM 的职责边界
- [ ] ❌ 方案中实际写了脚本代码（本 skill 只出方案）
