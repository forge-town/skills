# HTML 审查报告

## 读者入口

默认交付一份独立 HTML。多个 Issue 在同一文档中导航；简明检查结果、已填表单和折叠的生成正文均在文档内直接查看。禁止交付“MD 索引 → 单条 MD 报告 → MD 草稿”的阅读链；禁止把 Markdown 源码、iframe 或外链当作完整正文。

JSON、生成 Markdown、原生字段映射和校验记录继续保留为工作文件。HTML 只呈现这些已验证的数据，不另建业务表单或重写 Issue 生成模型。完整草稿直接由 assemble-issue.mjs 的输出渲染，正文、编号、顺序和表头不得人工改写。

## 视觉

使用会话中的 lv-editorial-pdf 技能，先读其工作流程、视觉规范和验收清单，使用它的 handbook 模板制作长报告；如果技能未在同级目录，按会话提供的路径读取，不伪造依赖链接。暖白、深棕、克制的陶土色、小字号正文和充足留白。独立封面仅居中标题，不加日期、署名、说明小字或装饰线。没有无业务含义的分隔线、圆角卡片或装饰图标。

只有用户要求 PDF 时再导出并逐页验收；明确只要 HTML 时不额外生成 PDF。HTML 字体和样式内嵌，不依赖远程 CDN 或其他 MD 文件才能阅读。

## 信息与交互

- 首页给出简短结论，每条 Issue 的检查结果只用“检查项／问题／怎么处理”三列。同一原因合并；不按每字段、每属性或每步骤生成读者检查行，不罗列全部符合项，不固定条数。
- 每条 Issue 只保留“检查结果”和“已填表单”两个主入口。表单展示实际字段标签及当前 JSON 的预填值，不是正文预览；基本信息、摘要、背景、任务、案例等章节都可切换查看。
- 表单的字段、顺序、必填、枚举和重复集合来自现有契约与 getFormContract／normalizeDraft，不复制一套业务字段定义。默认只读；未知必填项留空标“待补”，可选空值不报错。
- 任务、案例逐项展开。完整生成正文作为表单后的折叠对照，内容直接来自生成文件，不人工另写，也不取代表单。
- 窄屏保持页面无横向溢出，表单单列排布，操作按钮可触达。打印隐藏导航和操作按钮，展开全部表单章节、条目和正文；不只打印当前屏幕章节。
- 不修改 Linear 状态或属性，不把表单预填称为所有信息都已补齐。

## 生成和验证

使用 [HTML 生成脚本](../scripts/render-review.py)，输入只包含展示数据：title、intro、issues；每条 Issue 为 id、title、properties、verdict、checks（检查项、问题、处理三项）、formData（逐字读取当前表单 JSON）和 draftMarkdown。draftMarkdown 必须逐字读取当前生成文件，不从表单自行拼另一份正文。

```sh
python3 SKILL_ROOT/scripts/render-review.py --data PROJECT_ROOT/docs/issue-review/report-data.json --lv-root LV_SKILL_ROOT --output PROJECT_ROOT/docs/issue-review/review.html
```

以上路径为示意，替换为当前实际目录。脚本使用 lv-editorial-pdf 的初始化脚本和模板；更新已经授权的当前 HTML 时使用 --overwrite。Node.js 用于复用现有模型，Python 用于生成 HTML。输出和截图保留在当前项目 docs 下，不自动提交 Git。

交付前核对合并后的问题没有丢掉真实缺口、全部表单字段及预填值与 JSON 一致、生成正文未丢失、没有脚本错误或远程资源依赖；实际操作 Issue 导航、检查结果／已填表单切换、表单章节切换和条目展开；在宽屏、390px 和打印媒体核对截图。报告只写实际运行的验证，不把渲染成功当成产品验收通过。

## 标题与注脚

章节名称统一为“任务”“验收案例”，不加“抽象”“具体”等后缀。报告、表单预览和生成正文不添加“以下是预期结果，不表示已经执行或验收通过”等解释性注脚、过程说明或重复提醒；缺项放在对应字段和检查结果中，执行状态和真实证据仍如实保留。
