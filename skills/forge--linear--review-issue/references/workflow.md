# 执行流程

## 唯一来源

先读 [字段契约](../../forge--linear--show-issue-best-practice/references/issue-contract.json)、[生成模型](../../forge--linear--show-issue-form/assets/issue-model.mjs)、[写作标准](../../forge--linear--show-issue-best-practice/references/standard.md) 和 [可执行要求](../../forge--linear--show-issue-best-practice/references/executable-acceptance.md)。按当前 Feature／Bugfix 分支填表单，不另写字段或正文模板。

当前标准：任务直接以“前提条件／操作／预期结果”表达通用业务行为，案例关联任务。不再另设业务规则或用户流程章。Given／When／Then 只是内部框架，界面与正文使用中文。目标预期章下直接写内容，不重复标签，不添加解释性注脚。


## 读取和归位

通过用户自装 Linear MCP 读取正文、原生属性和必要来源。当前任务仅排版或整理本地报告时可以使用已有快照，说明实际范围，不声称重新验收实现。

标题、项目、负责人、状态、优先级和估点取真实原生值，不复制到正文基本信息章；未知属性不清空。模块只匹配已有标签或属性，不伪造 module 字段。

每段材料先归回表单：需求与痛点归背景、用户结果归目标、业务行为归任务、具体样例归案例。重复段落合并；没有对应字段的内容在内部记录说明去向。不得把额外结构藏进自由文本框，不为迁就一条 Issue 擅改字段。用户明确要求更新标准时才修改源契约和模型。

摘要三项保留，不因“摘要”章名删除。旧任务工程动作、输入输出条件、业务规则和流程保留到迁移记录；有用事实并入新任务或案例，不让读者再看两套重复说明。旧 BR 到新 T 显式记录映射，案例逐条核对 taskRef。

## 全量核查

1. 核对所选分支的所有章节、单值字段、必填、可选、枚举、顺序和额外内容；可选留空不报错。
2. 任务使用 T- 编号，名称、前提条件、操作和预期结果齐全；不重复维护另一套规则。
3. 每个案例的 taskRef 有效；每个任务有正面覆盖，整体覆盖必要反面情况。
4. 案例的前提只写当前必要状态；操作包含具体入口、控件、字面输入、顺序和检查点；预期结果明确。只输出一套中文操作，不重复步骤表。
5. 不设置执行元信息或完成条件章；不因缺账号、组织或环境 URL 另列缺项。必要业务状态直接写入前提条件。
6. 预期、实际状态、结果和证据分开。未执行不改成通过；未知根因不编造。
7. 生成内容取当前契约；没有源码、环境或原材料证据时不声称已核实或已实现。

## 报告

按 [HTML 交付要求](presentation.md) 生成一份 LV 风格 HTML，只有简明检查结果和已填表单两个主入口。检查结果只列实际需处理的问题，按同因合并为检查项／问题／怎么处理三列，不逐字段或逐步骤生成数百行审计表。

已填表单从当前 JSON 读取值，并复用契约和模型；未知必填保留空值标待补，不以生成正文或 JSON 源码代替表单。完整生成正文作为折叠对照，不额外加过程说明、版本尾巴或注脚。

## 生成与写回

先填平铺 JSON，包含 issueType。使用 [生成脚本](../scripts/assemble-issue.mjs)：

```sh
node SKILL_ROOT/scripts/assemble-issue.mjs --input PROJECT_ROOT/docs/issue-form.json --output PROJECT_ROOT/docs/issue.md --linear-output PROJECT_ROOT/docs/issue-linear.json
```

以上路径为示意，替换为真实目录。未知字段被拒绝；缺当前必填业务字段时正常生成阻断，保留草稿才加 --draft，不能称为可验收。

正文和原生字段映射全部取生成文件，不能生成后手工改章名、表头或内容。必要修改先改 JSON 或当前源标准，再重建。HTML 的生成正文与输出文件必须一致。

仅审查时不写回 Linear。授权写回后只提交请求范围的字段，正确原生属性不重复改；回读核对，不顺带改状态、评论、资源或历史资料。JSON、Markdown 和核查记录保留为工作文件，不交付多层 MD 阅读链，不自动提交 Git。

人物角色、姓名与简称按当前最佳实践使用标准斜体，由共用生成器处理；不得手写 HTML 标签。试用只修改用户授权的示例 Issue，不批量处理历史事项。
