# Check Component Consistency 执行确认清单

执行规则：**对比完成后逐项确认**

---

## 一、组件收集确认

- [ ] 已明确组件类型（Button/Page/Card/Input 等）
- [ ] 已收集 2+ 个同类型组件实例
- [ ] 已确认组件功能相似（同为按钮/同为页面）

---

## 二、实现特征提取

- [ ] 已提取各组件的 Props 接口定义
- [ ] 已提取事件处理方式（onClick/onChange 等）
- [ ] 已提取样式应用方案（className/style/css-in-js）
- [ ] 已提取 Hooks 使用模式
- [ ] 已提取 ref 转发实现
- [ ] 已提取错误处理模式
- [ ] 已提取子组件/组合模式

---

## 三、差异分析

- [ ] 已标记所有 Props 命名/类型不一致
- [ ] 已标记所有事件处理模式差异
- [ ] 已标记所有样式方案差异
- [ ] 已标记所有 ref 转发差异
- [ ] 已评估差异的合理性（有些差异可能是设计需要）

---

## 四、报告质量

- [ ] 报告包含总体一致率统计
- [ ] 每项差异都有具体的代码对比
- [ ] 提供了推荐统一模式（代码示例）
- [ ] 区分了"必须统一"和"可接受差异"

---

## Bad Case 确认（不得出现）

- [ ] ❌ 对比了不同类型的组件（如 Button vs Card）
- [ ] ❌ 只对比了业务逻辑（如按钮文字、颜色值）
- [ ] ❌ 遗漏了关键实现维度（如缺少 ref 对比）
- [ ] ❌ 报告只有差异列表，无统一建议
- [ ] ❌ 强制要求完全一致（忽略合理的设计差异）
